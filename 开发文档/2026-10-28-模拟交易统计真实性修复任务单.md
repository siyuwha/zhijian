## 问题与目标

当前 SimulationService.get_stats 把所有卖出计为盈利，无平仓时返回 66.7%，盈亏比固定为 1.8，而且仅取最近 200 条流水。目标是让模拟页展示基于该账户真实完整流水计算的统计结果。

- backend/app/services/simulation.py
- backend/app/schemas/simulation.py
- frontend/src/types/simulation.ts
- backend/tests/test_simulation_stats.py（新增）

业务代码修改限定为以上文件。若需要新增计算辅助模块或调整页面，先报告原因；不修改真实交易账本、回测引擎、T+1、自动执行、数据同步或生产数据。

## 统计与验收口径

1. 限定当前活动模拟账户，读取完整流水，不能截断为最近 200 条。
2. 依据现有 execute_trade 的实际处理顺序（流水 id 升序）及移动加权平均成本重建各代码的成本与持仓，支持加仓、部分卖出及卖清后重新建仓。与现有成交金额、均价和实际盈亏的舍入口径一致。
3. 一条有效卖出流水记为一个平仓交易腿；部分卖出也算一条。实现盈亏大于 0 为盈利，小于 0 为亏损，等于 0 为保本；保本计入平仓总数，不计为盈利或亏损。
4. 胜率 = 盈利平仓腿数 / 全部平仓腿数 × 100%；无平仓时 win_rate 与 closed_leg_win_rate 返回 null，有平仓时两者保持一致。
5. 盈亏比 = 盈利腿平均已实现收益 / 亏损腿平均已实现亏损绝对值；缺少任一类样本时返回 null，不返回虚构值或无穷大。
6. total_realized_pnl 与各有效卖出腿的已实现盈亏合计一致；total_trades 覆盖该账户全部流水。已有现金、市值和总资产字段含义保持一致。
7. 后端响应模型及前端类型允许上述 null；确认模拟页现有 '--' 空值展示可兼容，无需借此重做界面。
8. 本次不新增手续费模型或数据库迁移，不纠正历史流水，不调用生产接口进行交易或重置。若历史流水出现无成本卖出或超卖，统计请求返回 HTTP 409，说明异常流水 id 及原因；不静默忽略、不截断卖出数量后输出部分收益，不修改历史记录。
9. 保持现有服务方法签名及账户选择行为，不为测试便利扩展多账户交易、重置或查询接口；通过查询条件及测试夹具验证当前账户隔离。

## 必须验证的场景

- 无交易、只有买入：无平仓，胜率及盈亏比为 null。
- 单笔亏损：10 元买 100 股，9 元卖 100 股，已实现 -100 元，胜率 0%，亏损 1 笔，盈亏比 null。
- 单笔盈利：盈利 1 笔、胜率 100%，盈亏比仍 null。
- 保本卖出：平仓 1 笔、盈利/亏损均 0、胜率 0%，盈亏比 null。
- 同时有盈利、亏损：按实际各笔盈亏计算胜率及平均盈亏比。
- 加仓、部分卖出、卖清重买：成本和已实现盈亏正确，原有成本不串入新仓。
- 超过 200 条流水：早期买入成本和早期平仓计入全量统计。
- 多账户隔离：其他账户的成交不进入当前账户统计。
- 无成本卖出及超卖的历史记录：HTTP 409 明确拒绝统计，不返回伪完整的绩效数据。
- 部分卖出后再加仓的三位均价舍入，以及补录日期早于买入的卖出：统计顺序和现有记账结果一致。
