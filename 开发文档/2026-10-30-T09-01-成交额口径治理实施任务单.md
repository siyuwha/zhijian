## 一、裁决与目标

分析材料可用于实施设计，成交额口径尚未核准。报告参考函数不是验收标准，不继续以修改参考函数代替来源核实。

采用“先核准证据，再实现对应完整口径；无证据先安全降级”的顺序。将本任务拆为两个交付阶段：A 来源与规则确认、B 最小实现与验证。A 未取得全部证据不阻止 B 修复错误的完整性声明，但不能让未知字段成为完整市场总额。

目标：明确统计范围、日期、单位、时效、归档完成状态和质量；monitor、canonical、复盘及必要下游不再对未知或缺失数据宣称完整。

## 二、阶段 A：可信来源与规则确认

Antigravity 提供逐来源、逐接口、逐字段证据表：请求地址及参数、原始响应留存路径、采集时间和时区、真实交易日、证券/市场标识、金额单位、覆盖品种、统计阶段、归档完成语义、证据来源及核准状态。去除凭据后归档。

1. 分别核实沪市、深市和北交所“全市场成交额”的覆盖范围，不以指数名称、数值相等或数值量级推断全市场；不同提供方映射分别确认。优先核对交易所同口径统计及供应商字段定义。只证明股票成交额时，不扩称含债券等全部证券成交额。
2. 定义两市与全市场是否包含盘后交易及相应品种，两者采用一致边界。北证50字段未核准时不得当作北交所总额。
3. 盘后和历史完整性须有明确完成标识或可核验的来源归档规则，附依据；15:00、15:35 或数据连续稳定都不能单独证明最终归档。供应商更新时间与成交统计截止时间分别记录。
4. 明确各源零值是否表示真实无成交、占位、停牌或缺失，及有效零值所需字段。来源语义未确定就保持待核准。
5. 历史两份快照差额保留待核实；取不到当时原始数据时不追造数值，也不把新采样作为历史归因证据。

阶段 A 输出“已核准、待核准、不可用于该口径”清单及归档规则；Codex 独立核对证据。若外部访问受限，写明缺口，并进入 B 的保守降级路径，不宣称来源核准完成。新增外部源或付费依赖超出当前范围，另列方案。

## 三、阶段 B：最小实现范围

候选文件：backend/app/services/monitor.py、canonical_market_service.py、daily_review.py、相关提供方转换、契约及实际消费方。实施前追踪所有金额汇总与质量消费路径，按必要性确定真实修改清单；不进行无关行情、风控、UI 或存储重构。

### 1. 统一口径与质量

- 沪深不重叠、同口径市场总额才能相加；不再无条件累加四个指数。各分量保留来源和口径核准依据。
- 分别输出两市与全市场总额和质量，不共用一个模糊质量掩盖缺失。复用现有枚举；必要扩展时同步消费者并说明兼容性。
- FULL 同时要求组成市场齐全、字段口径核准、数字有效、目标日期和阶段匹配，以及该阶段的时效/归档条件通过。
- 任一必要分量范围未知、缺失、日期错误、过期或非法时，对应正式总额为 null，并保留各已验证分量及明确原因。不能把缺失视为零、单边值视为完整合计。
- 如需保留分析性估算，必须独立字段并明确不可作为正式市场总额；本任务默认不新增估算功能。
- 下游不把 null 转零，不继续以不可信总额驱动放量判断或复盘确定性结论；明确跳过、缺失或降级原因。

### 2. 日期、阶段与时效

- 使用 Asia/Shanghai、明确目标交易日及可靠交易日历，分别处理盘前、集合竞价、连续交易、午间休市、盘后、休市查询和历史查询。未来日期和未来报价时间拒绝。
- 各分量相对评估时点的年龄、各分量采样时差分别检查；对各来源明确阈值和边界。只有两侧时间一致不能证明新鲜。
- 实时路径必须事先记录阈值和含等号规则，测试阈值前、等于阈值和超限；不能沿用报告中冲突的 60 秒/300 秒规则。阈值需有来源更新频率与业务用途依据。
- 盘后未证实归档完成，即使超过 15:35 也不能 FULL；历史数据即使时间超过 15:00，也不能自动完整。历史结果以目标交易日和归档证据判定，不用当前时钟套用实时规则。
- 休市返回最近交易日值须标真实日期及历史属性，不冒充当日实时值。日历不可用时明确降级。
- 北交所执行相同级别的来源、口径、日期、时间、未来值与零值检查，不能只验证数字。

### 3. 数字与零值

- 单位有可核验出处，统一精度后先加总、最后展示舍入，避免分量提前舍入的累积误差。
- 拒绝 NaN、无穷、负金额；冲突字段不得任意取首个，按已确认来源规则选择，无法解决则降级。
- 有效零值必须证明该源在该阶段、该目标交易日的零值语义，并满足其必需字段；若需量额均为零，成交量缺失不能通过。
- 盘后或历史零值不默认有效，也不笼统默认非法；来源无证据时不标 FULL。北交所盘前零值同样检查时间和未来值。

## 四、强制验收矩阵

| 场景 | 必须满足的结果 |
| --- | --- |
| 已核准沪市 6000、深市 9000，另有创业板 3000、科创50 800 亿元 | 两市为 15000 亿元，不是 18800；这是已确认市场分量的假设算例，不证明指数映射 |
| 深市数值存在但范围待核准 | 两市正式总额 null，质量非 FULL，有口径未核准原因 |
| 沪深均核准且有效，北证50范围待核准或北交所缺失 | 两市可按自身条件完整；全市场 null、非 FULL |
| 缺沪市或深市；金额为空、NaN、无穷、负数 | 正式合计 null，缺失或无效原因可追溯 |
| 两侧同日同时间但同时过期 | 实时路径不能 FULL |
| 盘后 15:36、无最终归档证据 | 不能仅凭壁钟 FULL |
| 历史时间 15:00 后、无归档证据 | 不能仅凭时间 FULL；更换当前时钟不改变历史归档结论 |
| 已核准最终归档，日期及范围均符合 | 能产生可追溯的完整收盘/历史结果，不套用实时年龄淘汰最终归档数据 |
| 集合竞价、午休、休市日、日历不可用 | 分阶段输出，不能落入无条件盘后放行分支 |
| UTC 或其他时区输入，报价时间在未来 | 正确转上海时间并拒绝未来值 |
| 盘前金额 0、成交量缺失或来源零语义未知 | 不得标完整有效零 |
| 有来源证据的盘前有效量额 0 | 可明确保留 0，与缺失区分 |
| 历史零、北交所零、北交所陈旧/未来时间 | 独立校验，不借用沪深时间或质量 |
| 元/万元/亿元等价输入、小额多分量、字段冲突 | 单位一致，仅最终舍入；冲突按规则处理或降级 |
| 主备源切换或跨日缓存 | 不把不兼容统计口径、不同日期拼成完整合计 |

除汇总单元测试外，须覆盖 monitor、canonical、daily_review 的实际入口与至少一个下游消费路径。断言数值、null、质量、原因、来源日期及副作用；不能只测试报告参考函数或只核对测试数量。涉及展示变化再提供相应浏览器证据。
