## 一、版本号编制原则（SemVer 语义化规范）

系统采用标准语义化版本号格式：
$$\text{v}\langle\text{Major}\rangle.\langle\text{Minor}\rangle.\langle\text{Patch}\rangle$$

| 层级 | 位阶 | 变更性质 | 触发条件示例 |
| :--- | :---: | :--- | :--- |
| **主版本号** | `Major` | 重大架构颠覆 / 不兼容变更 | 核心数据流重构、破坏性 Schema 升级、MVP 阶段结束进入正式商用体系 |
| **次版本号** | `Minor` | **系统能力重大升级 / 里程碑交付** | **完成 P0/P1/P2/P3/M 系列重大功能体系落地**（例如 P2 多源数据弹性与健康治理） |
| **修订号** | `Patch` | **生产缺陷修复 / 紧急热修** | 生产环境 Null 安全防护、页面展示异常热修、单点协议兼容调整（0 夹带新功能） |

## 二、最高董事会自动化升级刚性铁律

> [!IMPORTANT]
> **最高董事会刚性约定（2026-09-29 确立）**：
> **“下次触发版本升级条件，必须在完成工作后自动升级，无需等待人工提示。”**

1. **里程碑完成即升**：
   - 当完成一个阶段（如 P2、P3）的代码落地、工程验收与生产部署后，负责的 Agent 必须主动执行次版本号提升（`Minor Bump`），打上对应 Git Tag 并固化入验收报告；
2. **热修收口即升**：
   - 当完成线上紧急缺陷热修（Hotfix）且浏览器端实测通过后，必须主动执行修订号提升（`Patch Bump`）；
3. **严禁版本欠账**：
   - 严禁系统内部已经迭代多轮功能，而界面与接口依然停留在历史旧版本号（如不能出现 P2 已经上线但依然显示 `v0.1.0 首战版` 的情况）。

## 三、单一真实源（SSOT）与工程化动态架构

系统建立前后端协同的单一真实源版本体系：

```
                    ┌────────────────────────┐
                    │ frontend/package.json  │ (版本号基础)
                    └───────────┬────────────┘
                                │
        ┌───────────────────────┴───────────────────────┐
        ▼                                               ▼
┌──────────────────────────────┐        ┌──────────────────────────────┐
│ frontend/src/config/version.ts│        │   backend/app/version.py     │
│ (前端应用运行时展示)           │        │   (后端探针与健康接口)       │
└──────────────┬───────────────┘        └──────────────┬───────────────┘
               │                                       │
               ▼                                       ▼
┌──────────────────────────────┐        ┌──────────────────────────────┐
│   Next.js 侧边栏 Version Badge│        │ GET /version / GET /health   │
│ (v0.2.0 P2 生产版 #commit)   │        │ (动态返回运行态 commit 与版本)│
└──────────────────────────────┘        └──────────────────────────────┘
```

1. **前端工程构建注入**：
   - [`frontend/next.config.mjs`](file:///d:/项目库/AI认知复盘交易系统/frontend/next.config.mjs) 在构建期执行 `git rev-parse --short HEAD`，将实际 Git Commit 与构建时间动态注入 `env`；
   - 侧边栏底部 Badge 直观呈现当前运行的版本号、阶段名与 Commit 哈希，一眼即可辨别是否命中旧缓存。
2. **后端动态探针**：
   - [`backend/app/version.py`](file:///d:/项目库/AI认知复盘交易系统/backend/app/version.py) 动态读取运行态环境变量或本地 Git 短号；
   - `/version` 与 `/health` 端点自动对齐，便于自动化冒烟探针巡检。

## 四、自动化升级工具使用 SOP

项目根目录下配备自动化升级工具 [`scripts/bump_version.py`](file:///d:/项目库/AI认知复盘交易系统/scripts/bump_version.py)：

### 1. 完成功能里程碑（次版本号升级）
```bash
python scripts/bump_version.py --type minor --stage "P3 实时计算版"
```

### 2. 完成紧急缺陷修复（修订号升级）
```bash
python scripts/bump_version.py --type patch
```

### 3. 同步当前 Git Commit 到版本配置
```bash
python scripts/bump_version.py --sync
```

### 4. 固化与打 Tag
升级后执行 Git 提交流程：
```bash
git commit -am "chore(release): bump version to v0.2.0"
git tag -a v0.2.0 -m "Release v0.2.0: P2 生产运行版"
git push origin master --tags
```
