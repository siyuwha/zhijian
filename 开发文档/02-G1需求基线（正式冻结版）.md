## 一、需求总览

### 系统目标

构建一套 AI 驱动的认知交易系统，将市场数据、交易逻辑、AI 认知、策略分析、风险控制以及 Human-in-the-loop 组织成一个可持续学习、验证、修正和积累的闭环。

### 用户角色

| 角色 | 说明 |
|------|------|
| **Owner（唯一用户）** | A 股个人投资者，系统的使用者、决策者和认知主体 |

> 本系统为个人使用，不考虑多用户、多角色、权限管理。

### 需求优先级定义

| 级别 | 含义 | 对应阶段 |
|------|------|---------|
| **P0** | 必须完成，系统基础 | Phase 1 |
| **P1** | 应当完成，核心闭环 | Phase 2 |
| **P2** | 可以完成，能力增强 | Phase 3 |

### S4. 数据采集层 [P0]

#### 核心原则

> **能力稳定，Provider 可替换。**

G1 要求系统具备某项数据能力 ≠ 要求必须使用某个具体接口。

#### 必须具备的数据能力

| 编号 | 数据能力 | 首选 Provider 候选 | 验收标准 |
|------|----------|-------------------|---------|
| S4.1 | A 股指数行情（实时/收盘） | 新浪 `s_` 系列 | 获取沪深创科指数数据，字段正确 |
| S4.2 | A 股个股行情 | 新浪无前缀 | 批量获取现价、昨收、成交量等 |
| S4.3 | 美股/亚太/商品隔夜数据 | 新浪 `gb_`/`b_`/`hf_` | 盘前可获取隔夜外盘数据 |
| S4.4 | 涨停池（情绪/连板/题材） | 同花顺 10jqka | 涨停总数、连板梯队、题材归因 |
| S4.5 | 指数日线结算数据 | baostock（Sina fallback） | 收盘后获取当日 OHLCV + 涨跌幅 |
| S4.6 | 盘前财经快讯 | 财联社 CLS | 获取最新快讯标题和摘要 |
| S4.7 | 新闻聚合 | 新浪新闻 feed | 获取财经新闻标题 |

#### 数据范围特别说明

> **交易/选股范围 ≠ 市场认知范围**

- 选股 Universe：**沪深主板 + 创业板**（科创板 688、北交所本期排除）
- 市场认知范围：**包含科创板和北交所**

科创板和北交所虽不进入 M6 选股候选池，但属于整体市场环境的一部分。在以下分析中必须纳入：

- 市场情绪 / 赚钱效应 / 风险偏好
- 资金流方向 / 市场风格
- 市场整体强弱 / 板块主题扩散
- 市场结构变化

> **不参与交易，不等于不参与认知。**

数据层和市场分析层不能简单地把 688/北交所数据完全过滤掉。

#### 架构要求

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| S4.8 | Provider / Adapter 解耦 | Provider 可替换、增加、降级和切换，不影响上层业务 |
| S4.9 | 统一错误处理与降级机制 | 任一 Provider 失败时不阻塞其他，标记数据质量（FULL/PARTIAL/FAILED） |
| S4.10 | 定时任务调度 | 按交易日历自动触发（盘前/竞价/盘中/收盘），非交易日不执行 |

#### 已知坑点（Preferred Provider 实施参考）

- 新浪：必须带 `Referer`；批量分 10 只一批 + `sleep(0.3)`；响应编码 GBK
- 同花顺：不提供炸板率；`reason_type` 按 `+` 拆分
- baostock：结算有延迟，需 Sina fallback，降级标记 PARTIAL
- 财联社：sign = md5(sha1(sorted query string))
- **铁律**：所有实时数据消费必须 `is_trading_time() and 价>0` 双查

### M1. 收盘复盘 [P0]

**场景**：每个交易日 15:30 后，系统自动生成结构化复盘报告。

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| M1.1 | 大盘总览 | 展示沪深创科四大指数当日涨跌幅、成交额、与前日对比 |
| M1.2 | 涨停分析 | 涨停总数、跌停总数、连板梯队统计、首板/回封/一字板分布 |
| M1.3 | 板块/题材归因 | 基于 reason_type 提取当日主线题材 Top N，展示板块集中度 |
| M1.4 | **市场状态与情绪指标** | 基于多指标综合计算形成市场状态与情绪指标；指标体系、权重及阈值支持配置与动态调整，并为 Cognition Layer 提供结构化市场状态输入。**G1 不冻结最终指标集合、权重及阈值。** |
| M1.5 | 复盘报告存储 | 每日报告持久化到数据库，可按日期查询历史报告 |
| M1.6 | 复盘报告 Web 展示 | 在前端以卡片/图表形式展示，手机端可正常阅读 |
| M1.7 | 数据质量标注 | 报告标注数据来源和质量状态（FULL/PARTIAL/FAILED） |

**用户故事**
> 作为 Owner，我希望每天收盘后打开系统就能看到当日的结构化复盘报告，帮助我快速理解当日市场全貌。

### M5. 盘中市场结构观察 [P2]

**场景**：交易时段内观察市场盘中结构，为认知、情绪判断、策略分析提供实时素材。

| **短线情绪层** | 涨停、炸板、连板、高标 | 市场短期情绪温度 |
| **核心结构层** | 龙头、核心股、高辨识度标的 | 市场结构性标的 |
| **资金/趋势结构层** | 容量中军、趋势核心 | 主流资金方向 |

#### 需求清单

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| M5.1 | 实时行情看板 | 展示指数、观察标的实时行情，自动刷新 |
| M5.2 | 短线情绪监控 | 实时展示新增涨停、炸板、连板、高标，按板块聚合 |
| M5.3 | 核心结构标的追踪 | 展示龙头、核心股、高辨识度标的的盘中表现 |
| M5.4 | 资金/趋势观察 | 展示容量中军、趋势核心的资金和走势 |

**边界约束**

**用户故事**
> 作为 Owner，我希望盘中能从情绪、结构、资金三个层面实时观察市场变化，为交易决策和认知积累提供素材。

### M6. AI 策略与选股 [P0 架构前置 / P2 逻辑实现]

> ⚠️ G0 约束：Phase 1 定位置和接口，具体选股逻辑 P2 实现。

#### 双模式支持

**模式 A：AI 自主驱动**
- AI 根据市场状态、已有认知、历史经验和策略空间主动发现/提出策略假设
- AI 主动形成策略并驱动选股
- 策略必须经过系统验证，不得直接进入真实交易

**模式 B：用户自定义策略**
- 用户提出策略需求、交易思路或规则
- AI 将其转化为结构化策略
- 系统执行选股并给出候选股票及理由

#### 选股范围

> **沪深主板 + 创业板**（科创板 688、北交所本期排除）

#### 需求清单

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| M6.1 | 条件选股引擎（支持双模式） | AI 自主和用户自定义策略均可驱动选股 |
| M6.2 | 候选池分层 | 筛选结果按 A/B/C 分层（A≥75 / B 50-74 / C<50） |
| M6.3 | 选股结果展示 | 候选池在 Web 端展示，含选入理由和评分依据 |
| M6.4 | 选股记录持久化 | 每日选股结果可回溯验证 |

#### 核心约束

- **候选池 ≠ 买入建议**
- AI 可以自主发现策略，但不能绕过 **Cognition → Strategy → Risk → Human** 直接形成真实交易执行

**用户故事**
> 作为 Owner，我希望系统既能让 AI 主动发现策略机会，也能让我输入自己的交易思路让 AI 转化执行，但最终买入决策由我做。

### M7. ~~选股回测~~ [已移除]

> **当前产品不建设独立的历史回测系统。**

移除原因：
1. 高质量历史回测对数据完整性和一致性要求高，显著增加系统复杂度
2. 历史回测容易受未来函数、幸存者偏差、数据窥探、过拟合等问题影响
3. 当前产品核心目标是验证 AI 认知和策略在**真实市场环境**中的实际有效性

> 未来如需历史回测，作为**独立 Backtest Engine / 独立程序**开发。可读取本系统策略定义，但不反向增加当前产品架构负担。

### M8. 前向模拟交易与策略验证 [P2]

**场景**：使用当前及未来的真实市场实时行情，按照系统产生的策略进行模拟交易，验证策略在真实市场环境中的实际运行结果。

#### 核心链路

```text
实时市场行情
  → Cognition
  → Strategy
  → 选股/交易计划
  → Risk
  → Human
  → 模拟执行
  → 模拟持仓
  → 实时盈亏
  → 市场结果
  → 复盘/反馈
```

#### 需求清单

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| M8.1 | 虚拟账户 | 创建虚拟资金账户，初始金额可配置 |
| M8.2 | 模拟买卖 | 以真实实时行情价格执行模拟交易 |
| M8.3 | 模拟持仓与盈亏 | 实时展示模拟持仓和浮动盈亏 |
| M8.4 | 交易决策追溯 | 记录每笔模拟交易的决策链路（Cognition→Strategy→Risk→Human） |
| M8.5 | 现实约束模拟 | 考虑成交、流动性、涨跌停等现实约束 |
| M8.6 | 前向验证报告 | 生成阶段性报告：判断准确率、策略有效性、认知偏差分析 |

#### 验证重点

- 当时系统为什么做出这个判断
- 策略是否真正产生了可执行的交易条件
- 实际市场是否按照判断发展
- 模拟执行中是否遇到成交/流动性/涨跌停等现实约束
- 判断与实际市场结果之间的差异

> M8 最终形成**认知 → 策略 → 模拟执行 → 市场反馈 → 复盘 → 学习**的前向验证闭环，与 Human-in-the-loop 和认知反馈机制直接衔接。

**用户故事**
> 作为 Owner，我希望在不投入真实资金的情况下，用实时市场数据验证系统的认知判断和策略是否真正有效，并通过模拟交易结果持续修正认知。

## 五、数据保留策略

### 原则

> **默认永久/长期保留，允许用户按条件自定义清理。**

### 分类保留策略

| 分类 | 数据类型 | 保留策略 |
|------|----------|---------|
| **核心资产** | Cognition 结果、策略、复盘、交易记录、Human Feedback、审计/验证记录 | **默认长期保留** |
| **高容量/可再生** | 原始行情、新闻原文、图片、缓存、中间计算结果 | **允许按用户配置清理** |

> 永久保留是默认策略，不代表永久禁止删除。系统必须同时具备历史追溯能力和可控的数据存储治理能力。
