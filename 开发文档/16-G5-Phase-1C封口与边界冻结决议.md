## 二、法定冻结边界清单（8 项铁律边界）

依据最高董事会指示，以下 8 项核心边界即刻进入**绝对冻结状态**，未经正式技术设计单与四权分立变更闸门流程，任何 Agent 均不得擅自突破或改写：

1. **M3 物理定位与限权边界冻结**：
   - M3 法定定位严格限定为“**09:25 开盘微观物理事实观测仪与状态承接器**”，绝不承担任何交易买卖决策；
   - 严禁产生任何买入、卖出、打板、低吸、追高或仓位配置等主观交易指令与诱导性建议；
   - 前后端全链路与作战看板逐项强制绑定“客观观察维度提示，非买卖建议”醒目免责声明。
2. **M2 → M3 兑现闭环事实验证契约冻结**：
   - M2 盘前推演作为开盘前客观观察基准与假设，M3 实施纯粹物理核对与事实验证；
   - 坚决排除任何“预测准确率打分”、“推演胜率评估”或命中率评级等主观伪命题，恪守物理事实记录。
3. **竞价量能比严格数学定义与对称分母冻结**：
   - 分子为两市竞价总额（上证+深证），分母严格直接锁定前日两市全天总成交（M1.4 `D6.total_amount`）；
   - 前日基准分母缺失或 $\le 0$ 时，比值严格置为 `None` / `'--'`，严禁硬编码伪造 8000/10000 亿等均值分母，坚决杜绝零填充与伪造数据。
4. **数据库 Schema 零变更刚性保护冻结**：
   - 严格复用现有 SQLite `auction_report` 数据模型，零 Schema 变更、零表结构迁移；
   - 统一通过既有强类型 JSON 字段（`index_open_data`, `one_word_count`, `high_open_stats`, `emotion_judgment`）序列化存储与解析。
5. **股票代码标准化与高标生态契约冻结**：
   - 纯数字代码自动按市场规则补充 `sh/sz/bj` 前缀（`_format_stock_code`），统一基于后 6 位数字安全无偏匹配；
   - 键名严格兼容易用同花顺 `max_height` 与 `lbc`，确保最高空间连板股、高标样本池溢价与一字板判定统计真实闭环。
6. **零填充防伪与空安全链式防御规范冻结**：
   - 缺失字段与异常数据显式保持为 `None`，前端统一安全渲染为 `'--'`；
   - 多级字典（如 D6 metrics 及连板梯队）全链路必须具备防御性安全链解构，杜绝运行时异常与白屏。
7. **1C 阶段红队发现缺陷正式注销（Closed）**：
   - 2 项 P1 级缺陷（高标池键名脱节、个股代码前缀补齐）与 1 项 P2 瑕疵（D6 安全链空防御）确认为彻底清零并闭环注销。
8. **跨阶段消费严格受控（变更闸门原则）**：
   - 后续阶段（包括盘中动态监控、策略承接层等）消费集合竞价数据时，**一律不得随意修改 1C 已冻结的 API 与数据契约**，必须单独发起技术设计单，走四权分立变更闸门。
