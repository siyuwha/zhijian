# A股个人 AI 复盘量化交易系统：底层数据架构与需求清单 (V2.0 整合归档版)

**文档版本**：V2.0  
**归档日期**：2026-10-10  
**系统目标**：支持 A 股市场行情分析、情绪周期研判、交易复盘诊断、策略回测、波普尔假说证伪与实盘知行合一盈亏归因。

---

## 一、 系统定位与数据总线设计

本数据层架构针对 A 股个人 AI 复盘与短线量化交易实战特性设计，以 **6 大领域核心层** 为业务底座，融合 **三阶段递进实施路线（P0 / P1 / P2）**，确保首期能以最低成本快速跑通闭环，中远期可平滑扩容至日内微观与多模态事件驱动。

```
┌────────────────────────────────────────────────────────┐
│                   AI 认知复盘与决策引擎                  │
└────────────────────────────────────────────────────────┘
                           ▲
                           │ 结构化事实输入
┌────────────────────────────────────────────────────────┐
│  Layer 5: 账户执行与“知行合一”日志层 (Trading & Review)  │
├────────────────────────────────────────────────────────┤
│  Layer 1: 真实大盘与情绪周期事实层 (Market Sentiment)    │
├────────────────────────────────────────────────────────┤
│  Layer 2: 标的微观行情与量价层 (Quotes & Microstructure)│
├────────────────────────────────────────────────────────┤
│  Layer 3: 板块主线与资金流向层 (Sectors & Money Flow)   │
├────────────────────────────────────────────────────────┤
│  Layer 4: A股特有交易规则与状态字典层 (Trading Rules)   │
├────────────────────────────────────────────────────────┤
│  Layer 6: 事件驱动与时间戳对齐层 (Events & Point-in-Time)│
└────────────────────────────────────────────────────────┘
```

## 二、 6大核心数据层详细需求矩阵

### Layer 1: 真实大盘与情绪周期事实层（复盘灵魂与环境锚点）
> **定位**：AI 判定市场处于“冰点、启动、发酵、分歧、退潮”周期的客观硬指标，为一切策略动作提供大盘环境基准。

| 数据类别 | 必需字段 / 统计指标 | 统计口径 / 计算公式 | 颗粒度 / 频率 | 优先级 |
| :--- | :--- | :--- | :--- | :---: |
| **全市场总量口径** | 沪深京三市真实总成交额、环比增缩量、成交量 | 严格去重与防双计校验（剔除基金转让、国债逆回购等，仅计 A 股竞价真实成交） | 日频 / 收盘后 | **P0** |
| **市场广度指标** | 真实上涨 / 下跌 / 平盘家数、全市场涨跌幅中位数 | 覆盖沪深京全 A 股（统计涨跌时剔除上市首日新股） | 日频 / 收盘后 | **P0** |
| **连板天梯矩阵** | 最高连板高度、各高度梯队个股列表、连板晋级率 | 连板晋级率公式：$\frac{\text{当日N板家数}}{\text{昨日N-1板家数}}$（如 2进3、3进4 成功率） | 日频 / 动态更新 | **P0** |
| **极值与极端指标** | 真实涨停家数、真实跌停家数 | **严格剔除 ST 股及当日上市新股**，真实反映短线情绪极值 | 日频 / 盘中与收盘 | **P0** |
| **炸板与亏损负反馈** | 真实炸板率、昨日炸板/破板个股今日平均折价率 | 炸板率固化公式：$\text{炸板率} = \frac{\text{炸板数}}{\text{封板数} + \text{炸板数}}$；用于衡量追高亏钱效应 | 日频 / 收盘后 | **P0** |
| **接力赚钱效应** | 昨日连板今日收益率、昨日涨停今日收益率 | 统计开盘表现（溢价）与收盘表现，衡量短线接力赚钱效应 | 日频 / 开盘与收盘 | **P0** |
| **两融与情绪资金** | 市场融资买入额、融资融券余额、主力资金净流入净额 | 全市场及主要宽基口径，衡量杠杆与活跃资金风险偏好 | 日频（T+1披露） | **P1** |

### Layer 2: 标的微观行情与量价层（日内推演与策略物理层）
> **定位**：支持 AI 进行日内微观走势推演、K线形态分析、买卖价位验证与精确回测。

| 数据类别 | 必需字段 / 内容 | 数据形态与要求 | 颗粒度 / 频率 | 优先级 |
| :--- | :--- | :--- | :--- | :---: |
| **日线行情** | 证券代码、交易日期、开高低收（OHLC）、成交量、成交额、涨跌幅、换手率 | 需配套提供前复权因子（用于形态与指标）与后复权因子（用于真实收益计算） | 日频 | **P0** |
| **宽基指数与ETF** | 上证指数、深证成指、创业板指、科创50、沪深300、中证500/1000、核心行业ETF日线 | 对齐个股走势，提供大盘 Beta 与行业走势基准 | 日频 | **P0** |
| **涨跌停分时与封单结构** | 首封时间戳、最后封板时间戳、盘中开板次数、封单金额、封单占流通市值比 | 用于精准评估涨停“封板硬度”、分歧转一致时间点与承接力度 | 分钟/快照 | **P1** |
| **集合竞价核心数据** | 9:25 开盘最终撮合价、竞价成交量、竞价成交额、未匹配委买/委卖金额 | 用于判断个股超预期抢筹、弱转强或开盘“核按钮” | 日频（开盘） | **P1** |
| **多周期K线** | 1分钟、5分钟、15分钟、30分钟、60分钟 OHLCV | 日内分时级别回测与执行点位对齐 | 分钟频 | **P1** |
| **竞价动态撮合流** | 9:15-9:25 虚拟撮合价格变动序列、匹配量、未匹配量变动序列 | 识别主力盘前虚假挂单、撤单试盘与诱多/诱空异动 | 秒级（竞价） | **P2** |
| **Level-2 盘口深度** | 逐笔委托、逐笔成交、十档买卖盘口快照、大单委托队列 | 高阶微观订单流、大单冲击成本与滑点精细化模型 | 毫秒/逐笔 | **P2** |

### Layer 3: 板块主线与资金流向层（回答“钱在哪里、主线是什么”）
> **定位**：让 AI 能够穿透单股，识别全市场资金聚集的主线题材、支线轮动及个股在板块中的领涨角色。

| 数据类别 | 必需字段 / 内容 | 业务规则与说明 | 颗粒度 / 频率 | 优先级 |
| :--- | :--- | :--- | :--- | :---: |
| **板块映射字典** | 行业板块（申万一级/二级/三级）、题材概念分类、成分股名单与权重 | 需记录成分股纳入/移出时间戳，防止历史回测出现“概念漂移” | 日频更新字典 | **P0** |
| **板块强度指标** | 板块涨幅榜、板块真实成交额、全市场成交额占比、板块内涨停个股数量与集中度 | 用于判断当前市场是“单一主线爆发”、“双主线共振”还是“混沌轮动” | 日频 / 盘中动态 | **P0** |
| **龙头/中军角色标注** | 身位龙（日内最早涨停）、空间龙（连板高度最高）、容量中军（板块成交额前两大市值核心） | 供 AI 归因板块驱动逻辑及标的带动力，研判情绪锚点 | 日频 / 动态标注 | **P1** |
| **板块资金流向** | 行业与概念主力资金净流入、超大单/大单主动买入占比 | 辅助研判机构大资金与短线游资合力方向 | 日频 / 分钟级 | **P1** |

| **交易日历** | 交易日期、开市/闭市状态、节假日安排、上一交易日/下一交易日指针 | 系统时钟基准，防止时间序列计算错位 | 预维护 / 年初更新 | **P0** |
| **股票基础信息** | 证券代码、股票名称、交易所、上市日期、退市日期、总股本、流通股本 | 基础标的池边界控制与生命周期管理 | 日频字典 | **P0** |

### Layer 5: 账户执行与“知行合一”日志层（交易复盘的核心引擎）
> **定位**：沉淀交易者与系统的真实操作轨迹，对比“策略预期”与“实盘执行”的差距，赋能 AI 进行心理与行为偏差诊断。

| 数据类别 | 必需字段 / 内容 | 首期建设方案与要求 | 颗粒度 / 频率 | 优先级 |
| :--- | :--- | :--- | :--- | :---: |
| **资金与持仓底表** | 交易日期、证券代码、持仓数量、可用数量、成本价、最新收盘价、持仓市值、账户可用现金、总净值 | 首期支持券商对账单 CSV / Excel 批量导入，保留原始快照 | 日频 / 收盘后快照 | **P0** |
| **委托与成交记录** | 委托时间、成交时间（精确到秒/毫秒）、买卖方向、委托价格、成交价格、委托数量、成交数量、撤单状态、交易规费（佣金、印花税、过户费） | 首期 CSV 导入 / API 对接。必须保留精确流水，用于计算真实执行滑点与摩擦成本 | 逐笔成交流水 | **P0** |
| **交易决策与假设日志** | 触发买卖的策略代码/模式、买入理由/逻辑假说、目标止盈价、预设止损条件、计划仓位比例、实际执行仓位 | **交易者结构化输入 / AI 交互辅助记录**。作为“波普尔假说”的起点 | 交易发生时 | **P0** |
| **复盘诊断与归因记录** | 实际盈亏金额、盈亏归因分类、执行偏差原因（冲动追高、未执行止损、恐慌抢跑等）、错误类型打标、改进动作承诺、复盘时间 | AI 基于市场事实与执行记录自动生成初稿，人工修正确认 | 每日收盘后复盘 | **P0** |
| **绩效统计指标** | 累计收益率、区间胜率、盈亏比、最大回撤、夏普比率、卡玛比率、基准超额收益（Alpha） | 周期性计算（日/周/月/年），评估策略与交易员进化曲线 | 日/周/月频 | **P0** |

### Layer 6: 事件驱动与时间戳对齐层（彻底消除未来函数）
> **定位**：实现时序点时间（Point-in-Time）对齐，确保盘后发布的利好绝不能被 AI 误用为盘中买入的归因。

| 数据类别 | 必需字段 / 内容 | 时间对齐规范与说明 | 颗粒度 / 频率 | 优先级 |
| :--- | :--- | :--- | :--- | :---: |
| **财务基本面数据** | 营业收入、归母净利润、扣非净利润、经营性现金流、资产负债率、净资产收益率（ROE） | **严格区分“报告期（如2024Q3）”与“实际公告披露时间戳（Point-in-Time）”**，回测时在披露时间前只可见上一期已披露财报 | 季频 / 随披露入库 | **P1** |
| **公司公告事件流水** | 公告标题、公告类型（业绩预告/快报、大股东增减持、资产重组、股权激励）、披露具体时间戳、PDF/正文摘要 | 以交易所官网正式挂网时间戳为入库生效基准 | 事件发生时 | **P1** |
| **盘中财经快讯时序** | 快讯标题、快讯正文摘要、信源渠道、资讯发布秒级时间戳、涉及证券代码 | 用于盘中异动驱动力复盘。回测时任何买入决策时间点必须晚于快讯发布时间点 | 实时/秒级 | **P2** |

## 四、 核心数据工程规范与防坑指南

1. **复权口径统一规范**：
   * **技术形态与指标分析（K线形态、均线、MACD等）**：一律采用**前复权（QFQ）**，保证价格图形连续性。
   * **资金净值回测与真实收益率核算**：一律采用**不复权价格 + 分红除权流水（或后复权 HFQ）**，防止分红派息造成的假性“回撤”或虚假“收益”。
2. **全市场成交额去重校验**：
   * 必须明确统计范围：$\text{全市场竞价总成交额} = \text{上交所A股竞价} + \text{深交所A股竞价} + \text{北交所竞价}$。
   * 严禁混入公募REITs、优先股、债券质押式回购（如 GC001 / R-001）和大宗交易金额，否则将严重扭曲市场增缩量判定。
3. **Point-in-Time（时间戳严格防未来函数）**：
   * 财务基本面数据入库时，主键必须包含 `announcement_date`（公告实际发布日），回测查询条件必须满足 `query_date >= announcement_date`。
   * 盘中复盘归因时，资讯事件的产生时间戳必须早于标的异动/买入时间戳，绝不允许“收盘后出的利好被当作盘中买入逻辑”。
4. **统一指标计算公式固化（ETL 层单点维护）**：
   * **真实涨停家数**：收盘价达到涨停上限且未停牌、非 ST、非首日上市个股总和。
   * **炸板率**：$\frac{\text{盘中曾触及涨停但收盘未封板家数}}{\text{收盘封死涨停家数} + \text{盘中曾触及涨停但收盘未封板家数}}$。
   * **昨日连板收益率**：昨日连板个股今日开盘/收盘相对于昨日收盘价的平均涨跌幅。
   * 以上核心公式必须在底层 ETL 统一固化产出，严禁各业务端独立编写不同口径的临时统计逻辑。

## 五、 数据源对接建议与落地指引

* **行情、复权与交易日历基础服务**：
  * 开源/低成本方案：AkShare、Tushare Pro、BaoStock 等。
  * 官方/商业级参考：上海证券交易所官网 (`sse.org.cn`)、专业金融数据供应商（如 `databull.cn`、同花顺 iFinD、聚宽/米筐等）。
* **账户持仓与成交流水**：
  * 首期方案：采用标准化 CSV/Excel 模版进行手动/半自动导入。
  * 长期方案：通过 QMT / 掘金量化 / 券商官方开放 API 进行日终自动同步。
