# AI 认知复盘交易系统 — 项目决策基线（G0 正式版）

- 基线日期：2026-09-21
- 基线状态：**已冻结（G0 通过）**
- 决策来源：Owner 最终确认
- 核心原则：**冻结当前决策边界，不提前锁死 G3 的认知模型具体实现**

---

# 一、11 项最终决策

### 1. 产品定位
本项目定位为**AI 驱动的认知交易系统**，而不是单纯的量化选股、指标分析或自动交易程序。

系统的核心价值是：

> 将市场数据、交易逻辑、AI 认知、策略分析、风险控制以及 Human-in-the-loop 组织成一个可持续学习、验证、修正和积累的交易认知系统。

---

### 2. 保留原技术栈，并增加独立 AI / Cognition Layer

确认：

- 原有技术栈继续保留；
- 不因为增加 AI 能力而推翻现有技术基础；
- 在原有系统之上增加**独立的 AI / Cognition Layer**；
- AI / Cognition Layer 必须具有清晰的架构边界、接口和职责，不应与普通业务逻辑混杂。

---

### 3. AI / Cognition Layer 前置到 Phase 1

确认将 AI / Cognition Layer 从后续阶段**前置到 Phase 1**。

原因不是为了提前完成全部认知系统设计，而是：

> Phase 1 的系统基础架构必须从一开始就为 AI / Cognition 能力预留正确的位置和边界。

因此 Phase 1 需要完成的是 AI / Cognition 的**基础架构与系统边界**，而不是提前完成 G3 的完整认知模型。

---

### 4. 选股能力前置

确认将**选股能力前置**。

选股不是系统后期附加功能，而应作为交易认知系统早期核心工作流的一部分。

但需要注意：

> "选股前置"并不意味着现在就冻结完整选股策略。

Phase 1 需要优先解决选股在系统中的位置、输入输出、与 AI/Cognition、Strategy、Risk 等层之间的关系，以及后续可扩展接口。

具体选股逻辑可以在后续阶段继续设计。

---

### 5. "交易认知"四个核心维度作为后续架构设计依据

后续系统设计必须保留以下四个核心维度：

1. **市场生态与情绪周期**
2. **技术形态与数据本质**
3. **盈亏同源与概率**
4. **自我边界与系统构建**

这四个维度是本系统"交易认知"的**产品/领域层原则**，后续认知架构设计必须以它们为重要基础。

但这里有一个非常重要的边界：

> 这四个维度现在不直接等价于数据库字段、固定程序规则、枚举值或具体算法。

不能简单地把它们硬编码成：

```text
dimension_1 = market_emotion
dimension_2 = technical
dimension_3 = probability
dimension_4 = self_boundary
```

然后以此直接锁死系统设计。

它们首先属于**Domain / Product Principle**。

具体如何将其转化为：

- Cognition Model
- Cognition Object
- Cognition Evidence
- Cognition Validation
- Cognition Correction
- Cognition Memory
- Long-term Accumulation

应当留到 **G3 正式设计阶段**解决。

这样既保证核心交易思想不会丢失，又避免在架构尚未充分讨论之前过早锁死认知系统的具体实现方式。

---

### 6. AI / Cognition Layer 必须采用独立架构

AI / Cognition 不是普通的一个 AI API 调用模块。

需要形成独立架构层，并明确：

- AI / Cognition 的职责边界；
- 输入与输出；
- 与 Market/Data 层的关系；
- 与 Selection / Strategy 层的关系；
- 与 Risk 层的关系；
- 与 Human-in-the-loop 的关系；
- 模型调用与模型编排机制；
- 后续认知积累、验证和修正的扩展能力。

具体 Cognition Model 不在 Phase 1 提前冻结。

---

### 7. Human-in-the-loop 必须保留

系统必须从架构层面支持 **Human-in-the-loop**。

人不是系统外部的临时操作员，而是认知系统的重要组成部分。

因此后续系统需要支持：

```text
AI / System Judgment
        ↓
Human Review / Judgment
        ↓
Feedback
        ↓
Validation
        ↓
Correction / Learning
        ↓
Long-term Accumulation
```

具体交互形式、反馈对象、验证机制等，在后续阶段继续设计。

---

### 8. 使用 G1 → G3 → G4 → G5 → G6 闸门推进

后续项目严格按照以下 Gate 体系推进：

**G1 → G3 → G4 → G5 → G6**

每个 Gate 都需要有明确的：

- 输入；
- 设计目标；
- 输出；
- 验收条件；
- 决策边界。

不能因为已经确定总体方向，就跳过正式 Gate 设计。

尤其是：

> G3 是认知架构正式设计的重要阶段。

因此本阶段只确定"交易认知的领域原则"，不提前替 G3 完成具体认知模型设计。

---

### 9. Git 必须初始化

项目必须从当前阶段开始正式建立 Git 版本控制。

要求：

- Git repository 必须初始化；
- 后续关键架构、代码和配置变化必须进入版本控制；
- 重要阶段形成明确 commit；
- Gate 之间形成可追踪的版本基线；
- 禁止继续以"目录里当前有什么文件"作为唯一版本管理方式。

Git 是后续架构演进和审计的基础设施，不是可选项。

---

### 10. NAS / Docker：以当前飞牛实际环境决定

部署目标继续以当前飞牛 NAS 环境为基础。

但：

> Docker 是否采用，不在架构层面强行预设。

应该根据实际部署需要决定。

也就是说：

- NAS 是当前主要部署环境；
- 应适配当前飞牛 NAS；
- 是否 Docker 化，由实际部署需求、服务隔离、依赖管理、维护成本等因素决定；
- 不为了"看起来标准"而强制 Docker；
- 也不因为当前环境方便而提前锁死部署方式。

---

### 11. Phase 1 暂不把外网访问作为核心工作

Phase 1 暂不以外网访问、远程暴露服务、公网部署作为核心工作目标。

优先完成：

> 本地 / NAS 环境下的核心系统架构、AI/Cognition 基础能力、选股能力及后续 Gate 所需基础。

网络访问、安全暴露、远程使用等问题，在确实进入相应需求阶段后再处理。

---

# 二、AI 模型协作方式

确认采用：

> **Opus + Gemini 双模型协作模式**

原则上：

- **Opus**：负责高层架构推理、复杂约束分析、系统设计、一致性检查等；
- **Gemini**：负责与其互补的设计分析、实现辅助、验证和审查工作；
- 两个模型不是简单的"一个主模型 + 一个备用模型"；
- 后续可以根据具体任务定义不同职责；
- 最终架构决策仍以项目正式 Gate 和人工确认结果为准。

具体模型分工可以在后续阶段进一步细化。

---

# 三、关于"交易认知"的特别说明

这是本阶段最重要的设计边界之一。

核心领域定义：

> 1. 市场生态与情绪周期
> 2. 技术形态与数据本质
> 3. 盈亏同源与概率
> 4. 自我边界与系统构建

是对"交易认知"的**核心领域定义 / 产品原则**。

它们代表系统需要理解的核心认知空间。

但是：

**不要现在直接把这四项转换成数据库 Schema、固定字段、程序规则或者硬编码分类。**

原因是我们现在还没有完成对"认知"本身的正式架构设计。

后续 G3 需要回答的问题包括：

1. 什么是 Cognition？
2. 什么是 Cognition Object？
3. 一个认知由什么构成？
4. 什么可以作为 Cognition Evidence？
5. 如何区分事实、观察、推断、假设、判断和结论？
6. 如何验证一个认知？
7. 如何判断认知被市场证伪？
8. 如何产生 Cognition Correction？
9. Human Judgment 如何进入系统？
10. 如何形成长期 Cognition Memory？
11. 如何避免系统把错误经验固化成错误规则？
12. 如何让认知随着真实市场结果持续演化？

这些问题应该在 **G3** 正式解决。

因此当前原则是：

> **现在冻结"认知方向"，不冻结"认知实现"。**

---

# 四、本阶段的核心边界

请不要因为已经确定了上述方向，就提前进行以下工作：

- 不提前设计完整 Cognition Schema；
- 不提前把四个认知维度硬编码；
- 不提前冻结 Cognition Object；
- 不提前冻结 Cognition Memory；
- 不提前把交易认知转化为固定评分体系；
- 不提前把认知变成简单的指标或规则；
- 不提前把 Human Judgment 简化成几个数据库字段；
- 不提前设计完整自动交易闭环。

当前阶段应该做的是：

> **建立能够承载未来交易认知系统的正确基础架构，而不是提前把未来的认知系统设计完。**

---

# 五、最终执行原则

后续所有设计和实现均以本文档为当前正式决策基线。

总体路线：

```text
Phase 1
│

├── AI / Cognition Layer 前置

└── 暂不以外网访问为核心
        ↓
G1
        ↓
G3
├── 正式设计 Trading Cognition Architecture
├── Cognition Model
├── Cognition Object
├── Evidence
├── Validation
├── Correction
└── Long-term Accumulation
        ↓
G4
        ↓
G5
        ↓
G6
```

其中最重要的原则：

> **Phase 1 负责把"承载认知的系统"搭起来；G3 负责正式回答"认知本身应该如何被系统化"。**
