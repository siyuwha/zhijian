## 二、第一层：G1 需求基线溯源（G1 规定了什么）

依据《02-G1需求基线（正式冻结版）.md》第 3.3 节，**M3 交易记录**属于 **P1 核心闭环需求**：

> **业务场景**：记录每笔交易操作，追踪盈亏，关联认知复盘。  
> **用户故事**：作为 Owner（唯一使用者），我希望系统帮我记录每笔交易的完整信息和心路历程，让我能清晰地看到自己的交易行为模式和认知演变。

### G1 需求条款逐项核验表

| 编号 | G1 需求项 | 原始验收标准 | G1 优先级 | 核心内涵 |
|---|---|---|:---:|---|
| **M3.1** | 手动录入交易记录 | 支持录入：股票代码、买卖方向、价格、数量、时间、交易理由 | P1 | 交易事实的真实手工录入来源 |
| **M3.2** | 标准化写入接口 | 提供标准 API，外部 Agent（OpenClaw/Hermes 等）可通过 OCR/信息提取后写入，但不作为系统硬依赖 | P1 | 统一写入契约，无论来源最终均进入统一结构 |

| **M3.6** | 交易记录查询 | 按日期、股票、盈亏等维度查询历史交易 | P1 | 交易历史台账多维追溯 |
| **M3.7** | 交易统计 | 胜率、平均盈亏比、最大回撤等基础统计 | P1 | 个人交易表现的基础事实量化 |

## 三、第二层：G3 系统架构与设计对照（G3 规划了什么）

依据《04-G3架构与详细设计（正式版）.md》分层架构与持久化设计：

### 3.1 架构分层职责
- **Service 层**：`TradingService`（负责交易记录入库、持仓更新、盈亏计算、复盘笔记关联，作为编排层，禁止写死假数据）；
- **API 路由层**：
  - `GET /api/v1/trading/records`：历史交易记录查询（分页、过滤）；
  - `POST /api/v1/trading/records`：新增交易记录；
  - `GET /api/v1/trading/records/{id}`：单笔交易详情；
  - `GET /api/v1/trading/positions`：当前有效持仓及最新盈亏；
  - `POST /api/v1/trading/notes`：添加/更新交易复盘笔记；
  - `GET /api/v1/trading/notes/{trade_id}`：获取指定交易笔记；
- **Persistence 数据库持久化表**（G3 第 4.2 节）：
  ```sql
  CREATE TABLE trade_record (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      code TEXT NOT NULL,
      name TEXT,
      direction TEXT NOT NULL, -- buy / sell
      price REAL NOT NULL,
      quantity INTEGER NOT NULL,
      amount REAL,
      trade_time TEXT NOT NULL,
      trade_reason TEXT,
      source TEXT DEFAULT 'manual',
      created_at TEXT DEFAULT (datetime('now'))
  );

  CREATE TABLE position (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      code TEXT NOT NULL UNIQUE,
      name TEXT,
      quantity INTEGER NOT NULL,
      avg_cost REAL NOT NULL,
      total_cost REAL,
      current_price REAL,
      floating_pnl REAL,
      updated_at TEXT DEFAULT (datetime('now'))
  );

  CREATE TABLE trade_note (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      trade_id INTEGER,
      date TEXT NOT NULL,
      mental_state TEXT,       -- 心理状态
      decision_logic TEXT,     -- 决策逻辑
      reflection TEXT,         -- 事后反思
      lessons TEXT,            -- 经验教训
      created_at TEXT DEFAULT (datetime('now')),
      FOREIGN KEY (trade_id) REFERENCES trade_record(id)
  );
  ```
- **Presentation 前端展示**（G3 第 6.1 节）：
  - 路由：`/trading` 综合看板，包含“当前持仓卡片”、“交易流水列表”、“录入弹窗/表单”、“复盘笔记”与“基础统计面板”。

## 五、第四层：M3 严格边界定义（明确“做什么”，严禁“做什么”）

为了坚决防止主开发擅自发散与范围膨胀，本次恢复执行设定刚性边界：

### 5.1 MUST DO（核心建设范围，做精做透最小闭环）
1. **真实手工记账（事实录入）**：
   - 具备友好的录入界面与标准 API，支持录入：股票代码（如 `600519`）、股票名称、买卖方向（买入/卖出）、成交单价、成交数量、交易时间、交易理由。
2. **持仓台账与盈亏计算引擎**：
   - **买入**：自动加仓，计算最新加权持仓成本均价；
   - **卖出**：自动扣减持仓数量，精确结算该笔卖出的已实现盈亏；清仓时持仓数量归零；
   - **浮动盈亏联动**：持仓列表联动现有数据层 `StockQuoteCapability`，获取最新收盘价/现价，动态反映浮动盈亏与涨跌幅。
3. **交易复盘心路笔记（承接 G0 认知内核）**：
   - 每笔交易或特定持仓可挂载复盘笔记（交易时心态、决策依据、事后反思、经验教训），支持查看与追加。
4. **交易台账多维浏览**：
   - 交易记录分页展示，支持按股票代码、买卖方向、时间范围筛选。
5. **最小量化统计**：
   - 累计已实现盈亏、当前持仓总浮盈亏、总交易笔数、胜率（盈利交易数/总平仓数）、平均盈亏比。
6. **页面完整产品化落地**：
   - 彻底废除 `Coming in Phase 3` 假占位符，实现真正可交互、可录入、可查看、响应式友好的 `/trading` 交易与持仓页面。

### 5.2 STRICTLY FORBIDDEN（严禁超纲与越权行为）
- ❌ **严禁引入券商实盘交易接口/自动下单/自动撤单**（本系统绝非量化自动柜台）；
- ❌ **严禁引入任何选股策略、买卖信号推荐或自动交易策略**（此为 M6 范围，严禁掺杂进 M3 记账本）；
- ❌ **严禁引入模拟撮合账户或复杂保证金利息计算**（此为 M8 前向模拟范围）；
- ❌ **严禁引入任何形式的历史分时回放或回测系统**（M7 已被 G1 永久移除）；
- ❌ **严禁修改已封口的 M1、M2、M3(竞价)、M4 现有代码和表结构**；
- ❌ **严禁在此功能未获用户端完整操作与红队放行前，自动开启下一个模块**。

## 六、第五层：可执行、可检验的验收条件（Acceptance Criteria）

在功能交付移交红队与闸门时，必须 100% 满足以下 6 项刚性验收指标：

1. **AC-1 数据真实性与闭环性**：
   - 用户在前端或 API 录入一笔买入记录（如买入平安银行 1000 股，单价 10.50 元），数据库 `trade_record` 与 `position` 准确落库；
   - 用户随后录入一笔卖出记录（如卖出 500 股，单价 11.20 元），系统自动结算已实现盈亏为 `+350.00` 元，持仓剩余 500 股，成本保持 10.50 元；
   - 持仓现价通过行情接口成功刷新，浮动盈亏实时动态呈现。
2. **AC-2 认知笔记关联性**：
   - 能够为上述交易绑定记录心理状态（如“冲动跟风”）、决策逻辑与事后反思，并在前端详情卡片中清晰回显。
3. **AC-3 前端零假数据与零占位符（符合铁律 9）**：
   - `/trading` 页面不再显示任何 `Coming in Phase 3` 或静态假点位；
   - 空数据时友好展示“暂无持仓”与“暂无交易流水”，有数据时真实渲染。
4. **AC-4 接口健壮性与防伪检查（符合铁律 1、2）**：
   - 股票代码合法性校验、数量必须为正整数、价格必须大于 0；
   - 卖出数量超过当前持仓时，后端拒绝非法超卖并返回明确业务错误码（如 400 Bad Request），绝不产生负数持仓漏洞。
5. **AC-5 测试覆盖与构建质量**：
   - 后端新增 `test_trading.py`，全覆盖买入、加仓、减仓、清仓、超卖拦截、盈亏核算、笔记关联等用例，测试通过率 100%；
   - 前端 `next build` 100% 编译通过，无类型报错，无 Lint 警告。
6. **AC-6 双端干净与灾备同步（符合铁律 7）**：
   - 本地 Git Working Tree 100% Clean；
   - 局域网连通状态下，所有交付 Commit 完整同步至 NAS 远端仓库。
