## 二、核心个股样本股与盘面微观可视化规范 (v0.4.7 ~ v0.4.8)

### 1. 样本股筛选数学定义与业务准则
在「知见」操盘手复盘工作台与盘前内参中，微观样本股的选择直接代表了前一日全市场最激烈的多空交锋阵地。旧逻辑采用模糊打分容易漏选或混入跟风杂毛，新逻辑确立了严格的刚性过滤规则：

- **目标候选池**：仅限定在**昨日收盘的全市场最高板（Tier_max）及次高板（Tier_max-1）**股票中选取；
- **总容量边界**：总数量严格约束在 `[0, 6]` 只之间（最少可为 0 只，最多不超过 6 只）；
- **层级纳入优先级**：
  1. **最高板全数无条件纳入**：首先将 Tier_max 梯队中的所有个股全部纳入样本股（例如 10 板新华传媒、5 板九阳股份等），确立全市场空间高度与情绪天花板；
  2. **次高板按新题材卡位筛选**：在 Tier_max-1 梯队中，若存在**代表新题材、新概念方向**的个股，则纳入该题材中**涨停封板时间最早（First Seal Time）**的那一只；同题材后排跟风标的坚决剔除；
  3. 若按上述规则筛选后的总数超过 6 只，则按成交额大小及封板硬度截取前 6 只；若梯队出现断层且无新题材，则样本股允许低于 6 只甚至为 0，坚决杜绝生搬硬凑。

### 2. 微观可视化与交互规范
- **取消鼠标悬停小窗口**：移除原有鼠标悬停在分时走势曲线上弹出的跟随浮层，杜绝在多图并列看板上的 DOM 闪烁与遮挡问题；
- **一票一色独立调色板 (Distinct Color Palette)**：
  - 杜绝多只样本股使用相近色调导致的视觉混淆；
  - 建立金融等宽配色映射表（Emerald 翠绿、Amber 琥珀金、Sky 天空蓝、Rose 玫瑰红、Violet 紫罗兰、Cyan 蓝青）；
  - 保证多只核心标的分时并列、分时与分时均价线叠加时的极高视觉区分度。

### 3. 时钟周期与定时任务校准
- **盘前早报 (Premarket Briefing)**：调度生成时间严格对齐至每个交易日早晨 **08:30**（涵盖前夜美股/中概股收盘走势、7x24 隔夜重大财经电报与昨日复盘推演结论）；
- **集合竞价探针 (Auction Probe)**：严格锁定在每个交易日早晨 **09:15 ~ 09:25** 窗口，9:20 之前捕获撤单虚假申报，9:25 刚性定盘时输出未撮合量与关键多空标杆的开盘承接探针。

## 三、系统 LLM API 接入与中转站动态设置体系 (v0.4.9)

### 1. 架构目标与中转站兼容性
为了让用户摆脱对固定服务端环境变量的依赖，能够在任何网络环境下自由切换主流大模型服务商，「知见」系统在 `/settings` 页面构建了企业级 LLM 接入层：
- **兼容 OpenAI 标准协议**：全面兼容 OneAPI、NewAPI 等聚合中转站端点；
- **主流预设一键切换**：内置 DeepSeek 官方 (`https://api.deepseek.com/v1`)、OpenAI 官方 (`https://api.openai.com/v1`)、聚合中转站模式及本地 Local 端点；
- **端点自动容错纠偏**：若用户填写的 Base URL 附带了 `/chat/completions`，系统在保存时自动识别并智能剥离末尾冗余路径，杜绝路径拼接 404 错误。

### 2. 本地持久化与热加载机制 (Hot-Reload)
- **物理存储路径**：`data/llm_config.json`；
- **重启高可用**：持久化于主数据卷中，Docker 容器销毁重建或 NAS 挂载重启不丢失；
- **热加载实现**：`LLMConfigService.save_config` 执行时，通过 `_apply_to_runtime` 同步更新 Python 运行时的 `settings` 全局对象与 `os.environ`（`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`、`DEEPSEEK_API_KEY`）；
- **凭证提供器**：新增 `LLMConfigService.get_runtime_credentials()` 方法，推演服务在每次被调用时动态获取最新未脱敏配置，实现修改即刻生效，无需重启后端进程。

### 3. 安全脱敏与往返延迟诊断
- **安全脱敏**：前端展示与日志打印一律执行掩码脱敏（保留前 4 位与后 4 位，中间使用 `****` 遮蔽），系统提供显示/隐藏明文眼睛图标；
- **真实往返连通性测试 (Test Connection)**：
  - 点击“测试连接”按钮时，后端向目标端点发送极简测试 Payload（`max_tokens=10`）；
  - 实时测量真实网络往返延迟（Latency ms）并回显；
  - 精确诊断错误：401 密钥失效、404 端点错误、429 频次受限或网络超时。

## 四、「AI 深入提问」智能推演引擎彻底重构 (v0.5.0)

### 1. 彻底铲除“1.68 万亿机械死板假模版”
- **根因回溯**：在旧版 `zhijian_transcendent_review_service.py` 中，`ask_ai_cognitive_query` 的 `except` 异常捕获块硬编码了一段静态伪分析字符串（“必须以今日盘面真实去重成交总额 1.68 万亿为第一边界... 波普尔式证伪点... 机制应对...”）。一旦 LLM API 未配置、请求超时或提取失败，系统便静默抛出这段假数据，导致提问任何内容均输出一模一样的八股文；
- **彻底根治**：
  - 彻底删除代码中硬编码的 1.68 万亿假模版；
  - 若调用发生异常，诚实告知用户具体技术故障原因（如未配置 API Key 或连接超时），并直接输出从系统底层实时检索到的【客观物理事实速报】，绝不使用伪造内容糊弄用户。

### 2. 三层数据分级优先级架构 (3-Tier Grounded Architecture)
为保证 AI 回答严谨求实、有理有据，系统确立了严格的数据源分层供给体系：

#### ① 第一优先级：知见每日落档数据库资料
- 绑定当前复盘基准日期（`target_date`，如 `2026-10-12`）；
- 从数据库读取权威的每日落档数据：去重真实成交总额、全市场涨跌比、涨停跌停家数、首板晋级率、空间高度标杆以及由「知见」系统生成的 11 章全景深度复盘研报全文。

#### ② 第二优先级：知见系统各实时/物理接口
- **智能实体识别器**：
  - 清洗 60 余种交易问答常用停用词（如“帮我”、“看看”、“分析下”、“怎么样”、“走势”、“能买吗”等）；
  - 提取 2~5 字符向东财模糊搜索接口发起精准命中，未完全匹配时采用 4/3/2 子串分词探测；
  - 实测对各类口语化提问（如“帮我分析中红医疗”、“看看海立股份今天走势”、“常山北明后市逻辑”）实现 100% 秒级精准定位对应股票代码与名称；
- **微观物理行情与盘口调取**：
  - 调取新浪股票即时行情接口，提取：最新价、涨跌幅、开盘价、昨收价、**日内最高/最低价、全天日内剧烈振幅**、全天成交金额、成交量、买一至卖一挂单量；
- **核心概念板块映射**：
  - 调取东财概念板块接口，获取关联的前 8 个核心概念题材；
- **个股最新快讯与异动线索**：
  - 接入新浪财经个股公告与最新资讯接口，即时捕获该股票最新的主力资金净买入、融资融券异动、重大公告与研报等 5 条关键线索。

#### ③ 第三优先级：外部网络快讯与开放金融知识库
- 接入财联社 7x24 盘中电报快讯接口与网络财经资讯检索；
- 当用户询问宏观政策、行业突发利好/利空或系统数据库未覆盖的背景时，系统自动调取外部快讯；
- 引导大模型充分调动其庞大的金融投研与商业逻辑知识库进行深度推导，**坚决杜绝因“系统未录入数据”而直接拒答**。

### 3. System Prompt 全面破除生硬教条
- **人设升级**：定义为「知见」首席投研顾问与智能推演助手；
- **因题制宜原则**：
  - **问系统功能与日常交流**（如“你到底可以做哪些事情”、“在干嘛”）：热情清晰、结构化地介绍系统的 11 章全景研报、连板天梯、竞价探针与反事实推演，自然交流；
  - **问具体个股/板块**（如“帮我分析中红医疗”）：紧扣真实物理行情（如中红医疗当日高达 13.74% 的日内振幅、深长上影线、9.59 亿充沛成交量）、所属板块、筹码换手、自救资金意图与次日 09:25 开盘探针阈值展开实战级剖析；
  - **问宏观政策与通识**：结合网络电报与金融知识库透彻解答；
- **回答风格**：严谨、专业、深刻、实战，杜绝僵化复读，不给盲目买卖指令但明确多空成立条件与风险防守边界。

### 4. 前端聊天记录按日期独立持久化
- 前端对话抽屉升级：使用浏览器 `localStorage` 并以 `review_chat_${date}` 为键独立保存各复盘日期的对话历史；
- 切换不同复盘日期或关闭窗口重新打开时，当前日期的 AI 深入提问记录完好保留，支持多轮深度追问。
