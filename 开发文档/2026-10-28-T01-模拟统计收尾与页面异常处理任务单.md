## 四、实现要求

### 4.1 统计状态与提示

- 明确区分首次加载、成功、失败及再次刷新。首次加载尚无结果时，不展示虚构的 0% 胜率、零盈亏或初始资产作为已获取结果。
- 统计失败时清空旧 `stats`，保存可显示的错误原因。HTTP 409 优先展示后端提供的流水 ID、原因等业务信息。
- 网络错误、HTTP 500、无法解析的响应或空统计结果，均视为统计不可用；没有可用错误信息时显示“统计加载失败，请重试”等明确提示。
- 提示放在统计区域附近，使用持续的文本状态；不依赖控制台、单独颜色或自动消失的交易通知。动态提示应可被辅助技术感知。
- 复用页面现有刷新入口进行重试，不新增自动重试或轮询。恢复成功后清除旧错误，并展示新结果。
- 统计刷新期间可以保留上次成功值，但必须标明正在刷新；一旦本次统计失败，就必须清空。
- 不允许较早的请求覆盖较新的统计结果或错误状态；如现有入口可能并发，采用最小的请求顺序控制或阻止重叠刷新。

### 4.2 失败时的指标展示

当统计不可用时，下列依赖统计的字段展示 `--`，不沿用旧值，不以 0 代替：

- 平仓腿胜率、盈利腿数、平仓腿数、盈亏比、已实现盈亏。
- 当前计算中依赖已实现盈亏的可用现金、总资产、总收益率、现金储备率和仓位比例。

持仓接口独立成功时，持仓列表、持仓市值及浮动盈亏可继续按其数据展示；统计失败不应使其他已成功接口的内容整体消失。本单不新增其他接口的完整错误处理体系。

统计成功且字段值为 0 时，必须展示有效零值。成功响应中的胜率或盈亏比为 null 表示缺少样本，与请求失败明确区分：字段显示 `--`，并在统计区域说明“暂无平仓样本”或“盈亏样本不足”，不显示请求失败提示。

### 4.3 保留业务口径与现有样式

- 保持统计按当前活动账户的完整流水及流水 ID 升序重建，不调整交易成本、舍入规则或已有方法签名。
- 一条有效卖出流水为一个平仓腿；部分卖出同样计入。保本计入平仓总数，不计为盈利或亏损。
- 页面将“已平仓周期”等可能误导的标签改为“平仓交易腿”，分子和分母含义写清；不把平仓腿胜率称为完整持仓周期胜率。
- 维持现有页面结构及金融数字等宽排版；涨红跌绿，缺失值使用中立样式，不给未知收益附加涨跌颜色。异常提示复用现有组件或样式，不开展视觉重构。

## 五、前端验收样例

使用本地页面和明确的模拟响应验证。成功响应沿用 `{"code":200,"data":{...}}` 结构；异常响应包含对应状态码和 `detail`。除专门验证部分失败的场景外，其他页面请求提供稳定的离线成功数据。

| 编号 | 操作与输入 | 必须观察到的结果 |
| --- | --- | --- |
| AC01 首次加载 | 延迟统计响应，页面尚未取得统计 | 有加载反馈；依赖统计的指标不是虚构的零值或初始资产 |
| AC02 有效零值 | 买 100 股 × 10 元，卖 100 股 × 9 元；统计返回胜率 0、亏损腿 1、平仓腿 1、已实现 -100、盈亏比 null | 胜率显示 0%；盈利腿/平仓腿为 0/1；已实现为 -100.00 元；盈亏比为 `--`，说明样本不足，无加载失败提示 |
| AC03 无平仓 | 空账户或仅买入：平仓腿 0，胜率与盈亏比 null，已实现 0 | 显示“暂无平仓样本”；胜率、盈亏比为 `--`，有效交易数和已实现 0 正常展示，资金区域可显示本次成功响应对应结果 |
| AC04 首次 409 | `GET /api/v1/simulation/stats` 返回 409，`detail` 为“模拟交易统计失败: 流水 ID 42 存在超卖异常” | 页面持续显示原因和流水 ID 42；统计及其依赖资金指标均为 `--`，不显示 0/0 胜或已实现 0.00 元冒充结果 |
| AC05 成功后失败 | 先成功显示胜率 50%、已实现 +100 元，再点击刷新使统计返回 409 | 原成功值全部清除；依赖统计的资金与比例不继续展示旧值或用已实现 0 重算的值；错误提示保持存在 |
| AC06 通用故障 | 分别模拟网络断开、HTTP 500 非 JSON 响应、200 空统计结果 | 显示明确统计失败提示；页面不崩溃；行为与 AC05 的清理要求一致 |
| AC07 恢复成功 | 从 AC04 或 AC05 出发，使用现有刷新入口返回新的有效统计 | 错误提示消失，新统计正确展示，依赖指标恢复；无须重新打开页面 |
| AC08 部分接口失败 | 统计返回 409，持仓、流水与策略接口成功；再反向验证统计成功而策略接口失败 | 前者成功区域仍可使用，统计区域明确失败；后者不能把成功统计标成失败 |
| AC09 提示独立性 | 统计失败提示出现后，触发无业务写入的通知模拟或等待超过 4.5 秒 | 统计提示不随交易通知消失或被替换；只有统计恢复成功才解除失败状态 |
| AC10 请求顺序 | 先发请求 A，再发请求 B；B 先返回新成功结果或新错误，A 随后返回旧结果；如果采用阻止重叠方案，则验证重叠入口被阻止 | 最终页面服从最新有效请求，较早结果不得覆盖新结果或复活旧统计 |

交易后的页面刷新复用同一加载路径，通过模拟刷新行为验证即可。本任务不要求为了复现故障向生产或持续运行的模拟账户下单。
