## 四、验收标准

| 场景 | 验收结果 |
| --- | --- |
| 质量日志唯一约束冲突 | 记录本次质量日志写入失败及原因；失败会话被正确回滚或关闭，后续日志写入成功，无未回滚会话连锁异常。验证冲突真实触发及两次写入结果。 |
| 日志失败与业务事务隔离 | 在独立业务事务中设置未提交变更，注入日志失败；验证日志失败不会提交或撤销业务事务；分别验证业务主动提交与主动回滚后的数据库状态。 |
| 快照持久化失败、行情有效 | 注入真实持久化失败并核对回滚；本轮风控仍获得一次执行机会，监控与风控状态及原因分别可查；检查资金、持仓和流水符合风控实际结果，不能仅断言函数被调用。 |
| 行情无效且质量日志失败 | 两个失败原因均可查；风控明确跳过，不得生成模拟成交；核对资金、持仓和流水均不变。 |
| 质量日志并发写入 | 使用独立会话并发写入；所有成功记录主键唯一，失败明确可见且会话可恢复，不能通过吞错伪称全部成功。记录并发量、成功/失败数量及异常。 |
| 正常链路回归 | 有效行情下采集、日志、风控正常运行；保留 T02 的 T+1、部分平仓、账本异常和事件分类，相关专项通过。 |
| 故障可观察性 | 失败和跳过不得标记为整轮完全成功；记录至少包括阶段、结果、时间、原因及关联标识。若某阶段无法持久化，说明备用可观察渠道及其局限。 |
| 事务归属与隔离环境 | 提供调用顺序、事务所有权、连接和失败后的状态证据；证明故障注入及成交测试使用隔离数据，未修改生产数据库。 |

验证应运行直接涉及的现有测试、T02 模拟统计与风控专项，以及新增的真实调度器故障注入；不得以复制实现逻辑的测试、单纯 mock 返回值或通过数量代替真实事务验证。执行命令、原始退出码、测试数量、日志路径及未覆盖情况均需记录。
