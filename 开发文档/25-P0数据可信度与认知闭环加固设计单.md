# 25-P0 数据可信度与认知闭环加固设计单

## 一、 顶层定位与核心原则

### 1.1 治理背景
2026-09-28（周一）首战结束后，系统虽然成功沉淀了 4 笔真实交易流水与全天部分核心市场数据（成交额 1.95 万亿、涨跌停 33/56、连板 5 板等），但暴露出一系列系统性断点：
1. **外部接口风控瘫痪**：东财接口因盘中无节流高频轮询被封，引发级联断流；
2. **全盘死刑缺陷**：系统原有“单一指标缺失直接判定整份复盘 INVALID”的机制，导致包含 1.95 万亿巨量成交和短线极端分化的有效信息被整体作废；
3. **认知对撞断路**：交易录入后未自动触发认知诊断，且底层存在 `Dict` 作为 `List` 迭代的严重语法 Bug（导致 `INDICATOR_PARSE_ERROR`）；
4. **持仓收盘价缺失**：收盘后持仓现价与浮盈被打入 `UNAVAILABLE`，缺乏日终收盘价平滑补偿；
5. **假说契约脱节**：竞价报告数据结构与假说核验代码不匹配，早盘失效断言无法运转。

### 1.2 核心工程原则（用户批示决议）
1. **P0 优先级绝对第一**：先做“数据可信度 + 交易认知闭环”，后做 P1 前端高频交互，最后单独立项 P2 盘中监控大改版。
2. **拒绝盲目对抗反爬，建立健壮数据管道**：系统设计目标不是提高对单一数据源的“抗封伪装”，而是建立：
   **减少请求量 + 本地 TTL 缓存 + 批量接口 + 数据源分层 + 熔断 + 智能降级 + 最终状态补偿** 的工业级数据管道。
3. **零伪造铁律不变，优化质量评分粒度**：
   - 彻底废除“单点故障全盘死刑”（`抓不到核心指标 → 整份复盘 INVALID`）；
   - 改为“指标级显式标注 + 整体可信度加权评分”（`哪个指标缺失 → 哪个指标 INVALID → 整体质量反映覆盖度与可信度`），最大化保留已采集到的真实物理事实。
4. **原始事实层与纠错业务视图严格分离**：
   - 原始交易记录（包括今天录入的 101 股）属于客观事实账本，**严禁直接 UPDATE 覆盖**；
   - 错误本身也是交易员行为认知数据；系统通过 `trade_ledger`（原始事实）与 `reversal/correction`（冲正对）派生出 `current_trade_view`（当前有效业务视图）。

## 二、 架构改造与模块详细设计

### 2.1 行情数据管道加固（Data Pipeline & Fallback）

```text
外部行情源 (Sina / Eastmoney / BaoStock / ...)
   ↓
DataService (统一门面)
   ↓
[本地内存 TTL 缓存 (15s~30s) + 请求去重]
   ↓
主数据源调用
   ├── 成功 → 规范化数据清洗 (统一 UTF-8 编码) → 返回
   └── 失败 → 触发熔断器 (Circuit Breaker)
              ↓
          切换备用数据源 (Fallback Provider)
              ↓
          仍失败 → 指标级标记 INVALID (附带 timestamp, freshness=EXPIRED)
```

- **数据新鲜度与来源元数据**：每个采集到的指标统一封装为：
  `{ "value": float, "source": str, "timestamp": str, "freshness": "REALTIME" | "DELAYED" | "EOD_COMPENSATED" | "EXPIRED", "validity": "VALID" | "DEGRADED" | "INVALID" }`
- **持仓收盘价终局补偿机制**：
  在交易时段外（15:00 之后），若无实时 Push 行情，系统自动调用日终收盘价接口（Sina / Eastmoney 批量日线收盘价），对持仓中的标的进行收盘价回填，计算最终持仓市值与当日浮动盈亏，禁止显示全屏 `UNAVAILABLE`。

### 2.2 市场状态引擎（M1.4）指标级质量判定与分级降级

- **当前缺陷**：
  若 D2（全市场涨跌比）或 D4（微盘股）缺失，整个 `CognitionMarketState.data_quality` 被直接判为 `invalid`，`composite_score = None`，`state_label = UNAVAILABLE_DUE_TO_DATA_QUALITY`。
- **重构方案**：
  1. D1~D6 各维度拥有独立的 `quality` 属性（`full` / `partial` / `invalid`）；
  2. 综合质量等级计算：
     - 若 6 个维度全部有效：整体为 `full`；
     - 若有效维度权重和 $\ge 60\%$（如 D1、D3、D5、D6 有效，仅 D2、D4 缺失）：整体为 `partial`（部分降级）；
     - 若有效维度权重和 $< 60\%$：整体为 `invalid`；
  3. 当整体为 `partial` 时：
     - 保留所有有效维度的真实测量值与物理状态标签；
     - 综合状态标签显示为有效维度加权结果并附带 `(部分维度缺失降级)` 提示；
     - 显式列出 `missing_metrics`，绝不虚构数据。

### 2.3 认知对撞诊断引擎修复与全自动触发

- **Bug 彻底根除**：
  - 修复 `backend/app/services/cognition_review.py` 中的 `diagnose_trade`：
    - `market_state.indicators` 实为 `Dict[str, DimensionState]`，直接使用 `.items()` 或键索引安全提取 D1、D3、D5 得分与状态标签；
    - 增加严格的字典/列表防御性校验，杜绝 `INDICATOR_PARSE_ERROR`。
- **全流程自动驱动**：
  - 在 `TradingService.add_trade_record`（录入交易流水）事务提交后，自动调度 `CognitionReviewService.diagnose_trade`；
  - 立即生成 `CognitiveTradeDiagnosis` 记录，建立交易发生时的市场六维切片快照，评估环境匹配度（`HIGH_MATCH` / `LOW_MATCH` / `EMO_DRIVEN` / `AMBIGUOUS`），初始状态为 `UNCONFIRMED`。

### 2.4 竞价推演假说客观核验数据结构对齐

- **数据契约修复**：
  - `AuctionReport.index_open_data` 的真实存储结构为 `{"indices": [{"code": "sh000001", "name": "上证指数", "price": 3820.82, "pct_change": -1.74, ...}]}`；
  - 重写 `verify_hypothesis` 中的竞价数据提取器，建立代码映射表：
    从 `indices` 数组中解析各核心指数竞价涨跌幅；
  - 按照假说预设的 `assertion_metrics`（如 `sh_open_pct_min` 等）执行客观比对，正确跃迁假说状态为 `PARTIAL`（早盘吻合进入收盘核验）或 `FALSIFIED`（触碰失效红线即刻证伪）。

### 2.5 事实账本与业务视图隔离架构

- **不可篡改事实账本（Truth Ledger）**：
  - `trade_record` 表作为底座，只追加、不修改；今天录入的 4 笔交易（包括 101 股）完整保留。
- **纠错与冲正机制（Correction / Reversal）**：
  - 纠错业务流：用户若纠错 101 股为 100 股，系统底层生成一条 `REVERSAL` 冲正记录与一条新的修正流水；
  - 业务视图（`current_trade_view`）：对账引擎自动过滤已冲正对，呈现当前有效持仓与真实有效流水；
  - 审计视图：可一键展开该笔流水的全生命周期（“原录入 101 股 -> 红字冲正 -> 修正为 100 股”），完整保留交易员的录入行为认知数据。
