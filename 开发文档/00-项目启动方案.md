# AI 认知复盘交易系统 — 项目启动方案

## 一、项目概述

### 项目目标
构建一套面向 A 股个人投资者的 **AI 认知复盘交易系统**，实现「行情数据采集 → 市场分析 → 策略选股 → 模拟验证 → 交易记录 → 复盘认知迭代」的完整闭环。

### 核心理念（继承自实战认知）
- **Learning Independence**：AI Suggests → Human Approves，不做硬规则自动执行
- **复盘必须落地**：每次复盘产出「可执行的策略调整」或「明确的认知修正」
- **LTV 验证**：买入前逻辑与标的一致性验证，无实证一票否决

### 产品形态
- **响应式 Web 应用（PWA）**，手机/电脑浏览器均可访问
- **NAS 部署（Docker）**，24 小时运行，局域网 + 外网可达
- **开发环境**：Windows PC 本地开发调试，完成后容器化部署到 NAS

## 三、功能模块与迭代计划

### 全部模块（8 大功能）

| 编号 | 模块 | 说明 | 优先级 |
|------|------|------|--------|
| M1 | **收盘复盘** | AI 生成每日复盘报告：大盘总览、涨停分析、板块轮动、情绪判断、主线归因 | P0 |
| M2 | **盘前简报** | 自动推送：隔夜外盘、财经快讯、今日关注、持仓提醒 | P0 |
| M3 | **交易记录** | 买卖操作记录、盈亏追踪、持仓管理、认知复盘笔记 | P1 |
| M4 | **竞价观察** | 9:15-9:25 竞价数据监控、集合竞价异动提醒 | P1 |
| M5 | **盘中盯盘** | 实时行情看板、涨停监控、板块异动 | P2 |
| M6 | **策略选股** | 基于条件筛选（板块共振、量价、位置）的选股引擎 | P2 |
| M7 | **选股回测** | 历史数据验证策略有效性，输出胜率/盈亏比 | P3 |
| M8 | **模拟交易** | 纸上交易，验证策略实际执行效果 | P3 |

### 迭代规划

#### 🏗️ Phase 1 — MVP（核心数据 + 复盘报告）
> 目标：跑通数据采集→存储→报告生成→Web 展示的完整链路

- **基础设施**：项目骨架、数据库设计、Docker 配置、CI 流程
- **数据采集层**：接入新浪（指数/个股）、同花顺（涨停池）、baostock（收盘结算）
- **M1 收盘复盘**：每日 15:30 后自动生成结构化复盘报告，Web 页面展示
- **M2 盘前简报**：每日 8:00 自动生成盘前简报（CLS 快讯 + 外盘数据）

#### 📊 Phase 2 — 交易闭环
> 目标：从「看」到「记」，建立完整的交易记录体系

- **M3 交易记录**：手动录入 + 盈亏自动计算 + 认知复盘关联
- **M4 竞价观察**：竞价期间数据采集与展示
- **数据源扩展**：接入东财（板块/资金流）、完善降级策略

#### ⚡ Phase 3 — 盯盘与策略
> 目标：从被动复盘到主动辅助决策

- **M5 盘中盯盘**：实时行情推送（WebSocket）、涨停监控
- **M6 策略选股**：条件选股引擎、候选池 ABC 分层
- **AI 对话能力**：基于已有数据的交互式问答（接入 LLM）

#### 🔬 Phase 4 — 回测与模拟
> 目标：策略验证闭环

- **M7 选股回测**：历史数据回测引擎、可视化回测报告
- **M8 模拟交易**：纸上交易系统、与真实行情联动

## 四、数据源规划（借鉴 Trading AI OS 经验）

| 数据源 | 接入阶段 | 提供能力 | 已知注意事项 |
|--------|---------|---------|-------------|
| **新浪 hq.sinajs.cn** | Phase 1 | 指数/个股实时行情、美股/亚太/商品、新闻聚合 | 必须带 Referer；批量分 10 只一批 + sleep(0.3)；编码 GBK |
| **同花顺 10jqka** | Phase 1 | 涨停池（情绪/连板/题材/龙头）、涨跌停统计 | 不提供炸板率；reason_type 按 + 拆分做归因 |
| **baostock** | Phase 1 | 指数日线（收盘结算）、历史 K 线 | 结算有延迟，需 Sina fallback |
| **财联社 CLS** | Phase 1 | 盘前快讯 | sign = md5(sha1(sorted qs))；两个参数变体 |
| **东方财富 eastmoney** | Phase 2 | 板块排行、涨停池(fbt/hybk)、资金流 | 盘外价=0 必须双查；ut 固定 token |

### 明确不接入
- ❌ TDX 本地接口（Owner 指令剔除）
- ❌ 竞价逐笔 / Level-2 / 封单深度（公开接口不可得）

## 六、开发流程约定

### 遵循九阶段闸门制（简化版）

本项目采用闸门控制：

1. **需求确认（G1）** → 你确认功能范围和优先级
2. **设计评审（G3）** → 你确认架构和数据模型
3. **开发前复核（G4）** → 你明确说「复核通过」后才开始编码 ⚠️
4. **开发实现（G5）** → 我写代码、你审查
5. **测试验证（G6）** → 自动测试 + 你手动验收

### 协作方式
- 每完成一个模块，提交代码 + 更新文档
- 你随时可以提出变更，走变更评估流程
- 复盘和认知修正记录到项目文档中
