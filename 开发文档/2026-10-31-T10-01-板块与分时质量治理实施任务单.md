## 三、契约定义

### 1. 内部与对外元数据

复用 DataQuality、Freshness、DataStatus、ProviderErrorCode，不把网络状态、内容质量与时间新鲜度混为一类。标准概念如下，优先映射已有字段，缺失时最小增补：

| 字段概念 | 约束 |
| --- | --- |
| capability / symbol | 区分 sector、concept_blocks、stock_trends；分时批次必须定位每个代码 |
| quality / freshness / status | 保留独立枚举；UNAVAILABLE 表示无可用数据，不以 FULL 空序列掩盖故障 |
| provider / fallback_used | 真实数据来源及是否备用/缓存，不能把东财返回值标作 TDX |
| trade_date / source_timestamp / received_timestamp | 真实数据所属交易日、源端截止时点及接收时间分别记录；接收时间不能冒充数据更新时间 |
| degradation_reason / error_code | 对外可理解原因及稳定机器码；内部错误不透出密钥、地址凭据或堆栈 |
| missing_codes | 批量分时缺失代码；与逐代码结果和汇总质量一致 |

对外若仍用 error_message 等已有字段，提供明确映射，不另建重复字段。source_timestamp 不明时保留 null，并说明来源时间未知，不以请求时间填补。Canonical 枚举无法表达内部 INVALID/FAILED 时映射为不可用并保留错误码与原因，不直接透出不兼容值。

### 2. 必须遵守的状态矩阵

| 场景 | 数据及质量契约 |
| --- | --- |
| 有效主源真实数据 | 按实际完整度 FULL/PARTIAL，时间按真实语义；不由 HTTP 200 单独决定 |
| 主源失败、有效备用源成功 | 返回备用数据，DEGRADED、fallback_used=true，注明真实来源及主源失败原因 |
| 部分代码有效、部分无可用数据 | 成功代码保留；失败代码为空序列并有独立 UNAVAILABLE 元数据；批次 PARTIAL，missing_codes 对齐 |
| 所有源失败且无可用缓存 | 分时为逐请求代码的结构化空序列，quality=UNAVAILABLE、freshness=UNAVAILABLE；板块按对应列表结构返回空，原因明确 |
| 允许展示的同目标交易日旧缓存 | DEGRADED + STALE，注明截止时间和失败原因，不能显示为当前实时行情 |
| 超过展示保留期限、来源日期未知或跨目标日期缓存 | 不作为该请求数据使用，返回不可用；历史查询命中同历史目标日不等于跨日污染 |
| 来源明确无记录的合法空结果 | 可标 EMPTY，须有阶段及业务语义依据，不等同断流；未知空结果不得 FULL |
| 能力未采集 | 明确未请求/未采集语义，不伪造上游失败或继承其他能力 FULL |

缓存展示容忍期与正常 TTL、目标交易日及分时阶段分别定义，给出依据和边界测试；不机械照搬实时快照 300 秒规则。预算耗尽、熔断、缓存命中和 Singleflight 路径也须执行同一日期及年龄校验。旧缓存被读取不得刷新其数据截止时间。

### 3. API 与 Canonical 兼容

保留现有可用业务数据形状，元数据采用兼容增补或统一适配，并同步全部实际调用方。若不得不改变数组为对象信封，先列契约变更和迁移路径；禁止仅改后端导致前端迭代崩溃。

Canonical 元数据按能力分别附带，不能用宏观 FULL 覆盖子项 UNAVAILABLE；相反，也不因非关键分时缺失而抹除已验证宏观事实。质量合成按实际用途定义。遵守已有快照指纹、黄金快照门禁和严格 schema：新增字段如属于事实载荷须同步生成、重算及读取验证，不直接破坏旧快照兼容，不改写历史指纹。

## 四、验收样例与验证层次

| 编号 | 注入条件 | 核心断言 |
| --- | --- | --- |
| A1 | 东财概念源失败，TDX 仅有行业代号 | 不调用该映射充当概念备用；返回对应不可用/合法已标明缓存，不伪造概念 |
| A2 | sector 分别超时、断连、403、429、解析错误 | 对应标准错误码，记录原始原因类别；无未知异常导致整个页面中断 |
| A3 | 主分时源失败，东财有真实有效数据 | 返回东财真实点、正确来源、DEGRADED；不重复无界请求 |
| A4 | 分时双源失败、无缓存 | 每个请求代码空序列、UNAVAILABLE；无合成点、无虚假 0 价，无过期图残留 |
| A5 | 两个代码中一个有效、一个失效 | 有效曲线保留，失败代码局部提示，PARTIAL/missing_codes 一致 |
| A6 | 同日旧缓存尚在展示容忍期；超过期限 | 前者 STALE 并显示真实截止时间；后者不可用；阈值前/等于/超过分别断言 |
| A7 | 昨日缓存、午夜跨日、目标历史日变更 | 不串用日期；历史同目标日可按历史规则展示；缺日期不得冒充当日 |
| A8 | 宏观 FULL、板块 DEGRADED、分时 UNAVAILABLE | 三项状态同时可见，前后端不互相覆盖；板块/分时不可用于暗示行情全量完整 |
| A9 | 质量元数据缺失或未知枚举的旧响应 | 消费者保守标未知/不可用，不自动 FULL，不抛未捕获异常 |
| A10 | 失败后恢复有效数据，再迟到旧失败响应 | 本轮正确恢复；旧结果不覆盖新结果；既有成功图表和局部提示状态对齐 |
| A11 | 预算耗尽、熔断、Singleflight 并发复用旧结果 | 不绕过缓存年龄校验，保留真实错误类别，质量记录失败不阻断业务或风控独立机会 |
| A12 | 快照含新增元数据及既有历史 schema | 指纹重算一致；旧快照读入规则明确，不破坏 T09 成交额置空及下游保护 |

先做 provider/registry、缓存与质量映射单元测试，再通过真实 API 路由验证元数据确实输出，通过 Canonical 实际入口验证传播。不可只测自建辅助函数。

浏览器须挂载真实组件并使用真实接口契约，提供有效数据正控、故障局部降级、旧缓存标识及恢复的 DOM/截图/请求证据；按轮次唯一标记证明数据加载完毕。不可用断言须证明输入进入实际消费路径，不以“页面没有值”单独证明防线。

回归运行 T03-01/T03-02 相关隔离故障与风控专项、T09 受影响契约/指纹与下游专项，以及前端类型检查和必要构建。固定时钟、隔离数据库和模拟外部响应；真实源/NAS 探测单独记录结果及未检项，模拟通过不得称实网可用。
