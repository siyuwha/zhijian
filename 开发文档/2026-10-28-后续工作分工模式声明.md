# 知见项目后续工作分工模式声明

生效日期：2026-10-28  
依据：项目负责人在本次会话中明确指定的工作分工。  
适用范围：知见项目当前进行中及后续所有需求讨论、设计、开发执行、代码审查与交付。

## 核心分工

**Work 做主要工作入口，Codex 做独立代码审查，Antigravity CLI 做受控执行。**

项目负责人于 2026-10-28 再次明确：该分工作为全局默认模式，知见当前及后续所有工作均遵循。用户后续明确调整职责时，以最新指示为准。

1. **Work：** 讨论需求、设计方案、制定计划，拆成范围和验收标准明确的任务单。
2. **Antigravity：** 按任务单编辑代码、运行检查，报告改动和未完成项。
3. **Codex：** 对照方案、任务单、实际代码差异和验证结果独立审查，指出问题并复审返修。

| 角色 | 主要职责 | 交付内容 |
| --- | --- | --- |
| Work | 承接项目负责人需求，组织讨论，维护项目上下文与优先级，形成设计方案、执行任务及验收标准，汇总审查结果与交付状态 | 需求说明、设计方案、任务范围、验收标准、决策与待办记录 |
| Codex | 依据当前代码、实际差异和验证证据开展独立审查，核对实现与需求的一致性，识别缺陷、回归及测试缺口；必要时独立复现关键问题 | 带文件位置和证据的审查意见、验证结果、剩余风险与待核实事项 |
| Antigravity CLI | 在明确的任务范围、验收标准和授权权限内读取项目、实施代码修改、运行检查并报告执行结果 | 文件改动、执行与测试结果、未完成项和阻塞事项 |

项目负责人保留目标、优先级和最终交付决策权。

## 协作流程

1. 项目负责人通过 Work 提出需求，由 Work 组织方案讨论并形成执行任务。
2. Antigravity CLI 按任务实施，记录改动范围、验证结果和未完成项。
3. Codex 独立检查当前代码与改动，必要时运行针对性验证，给出有依据的审查意见。
4. Work 汇总审查意见并组织修正；修正后的变更再次交由 Codex 核对。
5. Work 向项目负责人报告交付情况及仍需决策的事项。

该流程定义责任和交付关系；各工具间的任务传递以实际可用的连接方式为准。

## 执行与审查约定

- 执行任务需明确目标、文件或模块范围、验收标准及允许的操作；Antigravity CLI 按已授权范围执行。
- CLI 已验证的权限配置持续保留，新增权限随具体任务配置；模型及推理强度保持默认，除非项目负责人另行指定。
- 执行前记录工作区已有改动，保护未提交工作，避免覆盖或混入其他任务。
- Codex 以代码、运行结果和可复现证据作判断；执行方自述和历史设计文档作为核对材料。
- 审查结论区分已经验证的事实、源码确认的问题和仍待验证的风险；检查通过不自动等同于业务验收完成。
- 常规实现与修改由 Antigravity CLI 承担；需要调整角色分工时，由 Work 与项目负责人明确。
- 当前已有任务及修复接续推进，不因启用全局模式重复实施；已实施、已审查、已部署和业务已验收分别记录。
- 聊天名称、模型、计划模式或工作位置变化不自动改变角色职责。工具之间未实际完成交接时，不声称任务已经派发。
