## 一、讨论成果

### 1. 工具与模型定位

- Codex：偏"编码/工程执行"的智能体模式，适合在指定工作区内完成软件设计开发全流程协作，包括读写代码文件、执行命令、构建文档和可视化。
- ChatGPT Work（工作协作模式）：偏对话式的业务协作与知识问答，适合头脑风暴、方案讨论、内容整理。
- 模型选择原则：
  - 需要深度编码、多文件修改、执行验证时使用更强的编码向模型（Codex 模式）。
  - 需要快速讨论、文档草拟、非编码内容时使用对话向模型（ChatGPT 模式）。
  - 本项目（软件开发）以 Codex 模式为主线推进。

### 2. 软件设计开发流程框架（九阶段 + 闸门）

| 阶段 | 内容 | 出口闸门（Gate） |
|---|---|---|
| 阶段 0 项目启动 | 目标、范围、干系人、十问澄清 | G0 启动确认 |
| 阶段 1 需求梳理 | 需求清单、用户故事、验收标准 | G1 需求基线确认 |
| 阶段 2 功能与边界定义 | 功能清单、非功能需求、明确不做的事 | G2 边界评审 |
| 阶段 3 架构与详细设计 | 架构、数据模型、接口、UI 设计 | G3 设计评审 |
| 阶段 4 开发前复核 | 全量复核需求、边界、框架 | **G4 开发放行（用户明确确认"复核通过"）** |
| 阶段 5 开发实现 | 按设计实现、代码评审、持续集成 | G5 开发完成评审 |
| 阶段 6 测试 | 分级测试 S0–S3、缺陷闭环 | G6 测试通过 |
| 阶段 7 部署上线 | 上线顺序与检查清单、灰度/回滚预案 | G7 上线确认 |
| 阶段 8 运维与迭代 | 监控、复盘、变更控制 | 持续循环 |

关键控制机制：

- 需求基线：G1 后冻结，任何修改走变更控制流程（提出 → 影响评估 → 批准 → 更新基线）。
- 六条基线：需求基线、范围基线、设计基线、代码基线、测试基线、发布基线，逐一对应闸门。
- 测试分级：S0 冒烟 / S1 功能 / S2 集成与回归 / S3 性能与安全。
- 项目状态流：启动中 → 需求中 → 设计中 → 待开发（复核门）→ 开发中 → 测试中 → 待上线 → 已上线 → 迭代中。
- 协作约定：交付物放 `outputs/`，中间文件放 `work/`；用中文交流；每阶段出口需用户确认。

### 3. 开发前复核闸门（重要规则，用户指定必须遵守）

在进入实际编码（阶段 5）之前，必须提醒用户将前面所有的项目需求、设计边界、流程框架等全部复核一遍，用户明确确认"复核通过"后，才可开始开发。此规则长期有效。

## 二、下一步推进方向

当前阶段：**阶段 0 项目启动（尚未正式立项，属于"项目前"状态）**。

### 第 1 步：项目启动十问（本轮立即动作）

1. 项目目标：要解决什么核心问题？
2. 最终用户：谁在用？什么角色、什么场景？
3. 使用规模：多少用户、并发量、数据量级？
4. 平台形态：Web / 桌面 / 移动端 / 服务 API？
5. 技术约束：是否指定语言、框架、云厂商、合规要求？
6. 时间预期：期望交付时间和里程碑？
7. 质量底线：性能、可用性、安全的最低要求？
8. 预算资源：团队规模、开发周期、预算范围？
9. 现有资产：有无可复用代码、数据、接口、UI 规范？
10. 上线方式：一次上线 / 灰度 / 私有化部署？

### 第 2 步：需求梳理（阶段 1）

- 输出需求清单（编号、描述、优先级 P0/P1/P2、验收标准）。
- 输出用户故事（作为…我希望…以便…）。
- 确认边界：明确"本期不做"的清单。
- 完成后提请用户确认 G1 需求基线。

### 第 3 步：后续节奏

- G1 通过后 → 阶段 2 功能与边界定义 → G2 → 阶段 3 设计 → G3 → **G4 开发前全量复核（规则）** → 阶段 5 开发 → 阶段 6 测试 → 阶段 7 上线。
